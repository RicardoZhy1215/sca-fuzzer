analysis scripts, notes, and runs (under `runs/`).

## ctxrl on Spectre v1

- `space_v1ctx.py`: the config space (same interface as `space_v4`). It is SpecRL v1.yaml
  (CT-SEQ, SSBD on) plus several basic blocks. The categories are DATAXFER, LOGICAL, MISC,
  COND_BR, NOP, BITBYTE, CONVERT and FLAGOP, plus the optional BINARY, CMOV + SETCC and
  SEMAPHORE. PUSH and POP are left out: they write rsp, so Revizor filters out every form.
  At the CONTROL knobs this gives 860 SPEC tokens.
- How the work is split: the policy writes only the instructions inside the blocks.
  Revizor draws the block sizes (multinomial), the CFG and the jumps. The CFG and the jumps
  are seeded by the program's structure tag, so RERUN and EDIT reproduce them exactly.
- `configs/`: the yamls written by `space_v1ctx.write`.

Running it:

    cd ~/sca-fuzzer
    taskset -c 1-3 python rvzr/SpecRL/genbandit/tcenv.py --space v1 --mode bypass \
        --minutes 360 [--max-programs N] --out rvzr/SpecRL/genbandit/spectre_v1/runs/<name> \
        --action '{"program_size": 32, "n_bb": 3}' \
        --policy ctx --ctx-policy learn --ctx-mode rule2

`--action` only needs the knobs that differ from `space_v1ctx.CONTROL`.

## Revizor runs of a config

    rvzr/SpecRL/genbandit/spectre_v1/queue_revizor.sh <config.yaml> <n programs> [-i, default 50] [name]
    python rvzr/SpecRL/genbandit/spectre_v1/summarize.py      # one row per run, config diff vs configs/v1.yaml

- Each call copies the yaml into `runs/revizor-<name>-n<N>-i<I>-<date>/config.yaml` and queues the
  run detached. Queued runs take the executor one at a time (`.executor.lock`), and wait for any
  revizor/tcenv/ttk_bench process already running.
- When a run ends, `curve.txt` gets the violation total and the cumulative violations every
  1000 programs (from `revizor_curve.py`).
