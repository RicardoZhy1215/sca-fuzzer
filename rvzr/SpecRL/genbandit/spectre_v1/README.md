# Spectre v1 study

Everything new about Spectre v1 (bounds-check bypass) goes in this folder: code, configs,
analysis scripts, notes, and runs (under `runs/`).

## Earlier v1 material, left where it is

These files predate this folder. They stay in place because other code imports them or refers
to their paths.

- `../space_v1.py`: v1 config-knob search space (SpecRL v1.yaml: CT-SEQ, base categories incl.

- `../v1/`: the 48 config yamls generated by `space_v1.write`

## ctxrl on Spectre v1

- `space_v1ctx.py`: the config space (same interface as `space_v4`). It is SpecRL v1.yaml
  (CT-SEQ, SSBD on) plus several basic blocks. The categories are DATAXFER, LOGICAL, MISC,
  COND_BR, NOP, BITBYTE, CONVERT and FLAGOP, plus the optional BINARY, CMOV + SETCC and
  SEMAPHORE. PUSH and POP are left out: they write rsp, so Revizor filters out every form.
  At the CONTROL knobs this gives 860 SPEC tokens.
- How the work is split: the policy writes only the instructions inside the blocks.
  Revizor draws the block sizes (multinomial), the CFG and the jumps. The CFG and the jumps
  are seeded by the program's structure tag, so RERUN and EDIT reproduce them exactly.
- `configs/`: the yamls written by `space_v1ctx.write`.

Running it:

    cd ~/sca-fuzzer
    taskset -c 1-3 python rvzr/SpecRL/genbandit/tcenv.py --space v1 --mode bypass \
        --minutes 360 [--max-programs N] --out rvzr/SpecRL/genbandit/spectre_v1/runs/<name> \
        --action '{"program_size": 32, "n_bb": 3}' \
        --policy ctx --ctx-policy learn --ctx-mode rule2

`--action` only needs the knobs that differ from `space_v1ctx.CONTROL`.

## Revizor runs of a config

    rvzr/SpecRL/genbandit/spectre_v1/queue_revizor.sh <config.yaml> <n programs> [-i, default 50] [name]
    python rvzr/SpecRL/genbandit/spectre_v1/summarize.py      # one row per run, config diff vs configs/v1.yaml

- Each call copies the yaml into `runs/revizor-<name>-n<N>-i<I>-<date>/config.yaml` and queues the
  run detached. Queued runs take the executor one at a time (`.executor.lock`), and wait for any
  revizor/tcenv/ttk_bench process already running.
- When a run ends, `curve.txt` gets the violation total and the cumulative violations every
  1000 programs (from `revizor_curve.py`).

## Deploying on another machine

Everything needed is on the `spectre-v1` branch: the Revizor core changes these experiments
use, `base.json` (the instruction spec), and `configs/v1.yaml`.

1. Code
   ```bash
   git clone -b spectre-v1 git@github.com:RicardoZhy1215/sca-fuzzer.git && cd sca-fuzzer
   ```
2. Python. This machine uses Python 3.10, torch 2.11, scipy 1.15, numpy 2.2 and unicorn 1.0.3.
   ```bash
   pip install -e .          # Revizor's own deps from pyproject.toml (unicorn==1.0.3, ...)
   pip install torch scipy   # ctxrl only; CPU is enough
   ```
   Don't install `revizor-fuzzer` from PyPI and rely on it. Everything is started from the
   checkout root (`python revizor.py ...`), so the checkout's `rvzr/` is what gets imported.
   It must stay that way, because the PyPI package lacks the core changes (e.g. `input_value_mix`).
3. Executor kernel module (needs `linux-headers-$(uname -r)`):
   ```bash
   cd rvzr/executor_km && make uninstall; make clean && make && make install && cd -
   ```
4. Check, then run:
   ```bash
   rvzr/SpecRL/genbandit/spectre_v1/queue_revizor.sh rvzr/SpecRL/genbandit/spectre_v1/configs/v1.yaml 100
   python rvzr/SpecRL/genbandit/spectre_v1/summarize.py
   ```
   The scripts use the `python` on PATH, or `$PY` if set.

Results depend on the CPU, so record it with every run set. The machine the first results came
from is an AMD Ryzen 7 8700F (Zen 4), 8 cores online (CPUs 8-15 offline), SMT off, microcode
0xa705208. ctxrl (`tcenv.py`) pins the fuzzer to cores 1-3 and the learner to 4-7, so it needs
at least 8 cores, or `--learner-cores` must be changed.
